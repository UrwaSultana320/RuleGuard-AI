Approved degree-aware revision

Select Bachelor’s or Master’s explicitly before upload. The same combined model response assesses each document; backend-owned references support preliminary scope assessments. A supported exclusive mismatch blocks without a report. Ambiguous scope requires acknowledgment before held findings are revealed. Mixed documents compare only the selected/general branch. Input edits invalidate the gate, held report and review choices. No authenticity, currency or completeness guarantee. New live reasoning remains unverified; Gemini usage stays 40.

Three code stops

  1. src/app/api/compare/route.ts → POST: validates requests, acquires global quota protection before live analysis, extracts sources and streams stages, sources, a report or a safe error. src/server/gemini.ts → analyze makes the normal token-count and single combined generation requests only when authorized access is enabled.
  2. src/server/evidence.ts → buildReport: resolves references against server-owned passages. Matching IDs establish source identity, not correct AI interpretation. Unsupported references are rejected; uncertain applicability can remain Insufficient Evidence.
  3. src/components/ResultsDashboard.tsx → FindingCard / emailText: displays findings, independent review choices and source-referenced email drafts. Acceptance does not certify accuracy or completeness.

Degree-aware code route

src/components/CompareForm.tsx requires explicit degree selection and loads accurately labeled samples. src/shared/schemas.ts requires each document assessment and rule-degree evidence. src/server/evidence.ts rejects invalid references and other-degree rules in findings; src/shared/applicability.ts gives a supported mismatch priority over uncertainty. src/components/DegreeApplicability.tsx shows both statuses before findings. src/state/session.tsx holds the same validated response until continuation; degree/document edits invalidate the gate, acknowledgment and reviews. No new AI call or storage service.

Where data lives

  • src/state/session.tsx → SessionProvider / useWork: browser memory retains work through navigation, errors and retries. Refresh/close clears it; there is no document database or browser storage.
  • Gemini: permitted public/synthetic content is processed under Google's separate Free Tier policies. App memory-only handling does not imply provider deletion.
  • src/server/quota.ts → acquire / reserve: Upstash holds temporary counters, leases and token-budget metadata only, never source content, applicant facts or reports.

To change this, start here

  • Limits: src/shared/limits.ts → LIMITS. Keep frontend and backend checks aligned.
  • Reasoning instructions: src/server/prompt.ts → instructions and src/shared/schemas.ts → rawSchema. Offline tests cannot prove a new prompt improves live reasoning.
  • Conditions and uncertainty: src/components/RuleInterpretation.tsx → RuleInterpretation / UncertaintyNotes. Empty lists mean not established; groupings remain unverified.
  • Complete source text: src/components/FullSourceView.tsx → FullSourceView. Preserve all supported passages and references.
  • Responsive design and focus styles: src/app/globals.css. Check both input and expanded results on mobile and desktop.

A practice to reuse

The first S01 application failure lacked enough diagnostic detail to identify its exact cause. Specific safe error codes and offline regression tests improved observability. A later authorized generation passed integration while still producing reasoning-quality defects.

Separate integration, reference integrity and reasoning quality. Reproduce failures before changing checks; do not weaken evidence validation to obtain a successful-looking report.

Evidence: tests/unit/evidence-diagnostics.test.ts, tests/unit/quality.test.ts, tests/e2e/local.spec.ts and devpost/checklist.md. Private saved output is optional offline test material, never runtime fallback data.
